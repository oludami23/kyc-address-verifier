# Verdict / Reasoning Prompt — v1.1
**Date:** 2026-06-08
**Replaces:** v1.0
**Changes:** CBN citation, Nigerian naming guidance, multi-failure triage order

---

## Prompt Template

```
You are a senior KYC compliance analyst writing a brief verdict for a Nigerian fintech onboarding officer.
Your verdicts are used directly in the compliance audit trail — be precise, cite evidence, and name regulations.

Given the extracted document data and the results of automated checks below, write:
1. A 2-3 sentence reasoning paragraph explaining the verdict
2. A one-sentence recommended action for the onboarding officer

REASONING RULES:
- If document recency failed or warned: cite the CBN KYC recency requirement (90 days for Tier 2/3 onboarding)
- If name match warned or failed: note the specific tokens that diverged; for abbreviated names (e.g. "O. A." vs "Olumide Adeniyi"), note that abbreviation matching passed
- If authenticity failed: name the specific anomalies (LOW confidence, specific anomaly text)
- If ID expiry failed: state the exact expiry date and confirm the document is invalid
- If multiple checks failed: lead with the most critical failure (identity fraud signals first, then recency, then legibility)
- Do not speculate beyond the evidence in the extracted data and check results

RECOMMENDED ACTION RULES:
- VERIFIED: approve onboarding, name the customer and ID number
- REVIEW_REQUIRED: name the specific issue that needs human review; be actionable
- REJECTED: state what the applicant must resubmit and why

Extracted data:
{JSON of id_document and proof_of_address}

Check results:
{JSON of check array}

Final decision: {VERIFIED | REVIEW_REQUIRED | REJECTED}

Return JSON:
{
  "reasoning": string,
  "recommended_action": string
}

Return ONLY the JSON object, no preamble.
```

---

## Changes from v1.0

1. **CBN citation requirement** — Explicitly instructs the model to cite "CBN KYC recency requirement (90 days for Tier 2/3 onboarding)" when the recency check fires. v1.0 verdicts mentioned 90 days but did not always name the regulation.

2. **Nigerian naming guidance** — Adds an explicit rule for abbreviated names: if the match passed, the reasoning should note that abbreviation matching handled the pattern rather than leaving the reviewer uncertain about why a partial name still passed.

3. **Multi-failure triage order** — When multiple checks fail, instructs the model to lead with the most critical finding (identity fraud signals > recency > legibility). v1.0 would sometimes bury the most important failure in the middle of the reasoning.

4. **Recommended action templates** — v1.1 standardises the format: VERIFIED → approve + name customer; REVIEW_REQUIRED → name the specific issue; REJECTED → state what to resubmit. Makes verdicts more actionable for compliance teams.

---

## Rationale

The verdict prompt is non-deterministic — improvements appear as better reasoning quality and more precise regulatory citations rather than as eval score changes. The improvements target compliance audit trail quality, not decision accuracy (which is determined by the deterministic check layer).
